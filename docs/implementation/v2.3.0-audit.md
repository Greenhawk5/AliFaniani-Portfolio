## 2. Root-Cause Analysis of Key Issues

### 2.1 3D Project Board Lag & Navigation Delay (CRITICAL SMOKING GUN)
**Inspected files:**
- `src/components/three/ProjectBoard.tsx` (lines 44–57)
- `src/three/screens/boardScreen.ts` (lines 142–174)
- `src/three/env.ts` & `src/three/timeEngine.ts`

**Verified Root Cause:**
1. **Clock Domain Mismatch:**
   In `boardScreen.ts`, `advance()` sets:
   `transitionStart = performance.now() / 1000` (which is in real elapsed seconds since page load, typically hundreds or thousands of seconds).
   However, `useFrame` in `ProjectBoard.tsx` calls:
   `renderer.update(env.time)`
   where `env.time` starts at `0.0` and accumulates `Math.min(dt, 0.1)`!
2. **Permanent Transition Lockout:**
   Because `env.time - transitionStart` evaluates to a negative number (e.g. `5 - 1450 = -1445`), `t = (elapsed - transitionStart) / 0.7` is never `>= 1.0`.
   As a result:
   - `transitionStart` is never reset to `-1`.
   - `advance()` and `back()` contain `if (transitionStart >= 0) return`, which permanently blocks manual navigation.
3. **Continuous GPU Texture Upload Loop (60/120 Hz):**
   Because `transitionStart >= 0`, `renderer.update()` continuously executes the transition rendering code (`drawSlide` with multiple radial/linear gradients, 52 line strokes, text measurements, and canvas snapshot blits) and returns `true` on EVERY frame.
   In `ProjectBoard.tsx`:
   ```ts
   if (renderer.update(env.time)) {
     texture.needsUpdate = true
   }
   ```
   `texture.needsUpdate = true` forces WebGL to re-upload the entire 1024x620 canvas to GPU VRAM 60 to 120 times per second, creating severe frame drops and thermal throttling.

**Solution for v2.3.0:**
- Unify the clock domain using standard seconds clock or delta-based interpolation.
- Introduce dirty-flag rendering: render static card backgrounds once to an offscreen buffer.
- Only mark `texture.needsUpdate = true` when an actual visual transition step or slide switch occurs.
- Allow immediate responsive user click navigation without locking out clicks.

### 2.2 Visitor Counter in 3D Developer Room
**Inspected files:**
- `src/components/three/ShelfDecor.tsx` (`Posters` component, lines 84–143)
- `src/components/three/DigitalClock.tsx` (position `[3.6, 3.02, -4.42]`)

**Findings:**
- Directly below the Digital Clock on the back wall, at position `[3.9, 1.72, -4.44]`, sits the Branded Logo Board (`Posters`).
- Currently, this board loads `/favicon.svg` into an offscreen canvas and displays the logo with an emissive material.
- We can display real visitor stats below the logo (e.g. "VISITS: 1,420" with a live pulse indicator).
- The canvas texture must be rendered once upon receiving analytics stats, with zero continuous per-frame reallocations.

### 2.4 Projects Page Responsive Grid
**Inspected files:**
- `src/pages/Projects.tsx` (lines 63–129)

**Findings:**
- Grid uses `md:grid-cols-2 xl:grid-cols-3`.
- In mobile and mid-sized tablet viewports, card descriptions and action buttons (`View details` / `Repository`) can become uneven due to varying title lengths and technology tag wrapping.
- Needs flexbox alignment (`flex flex-col h-full mt-auto`) and consistent padding across 320px–1920px viewports.

### 2.5 Admin Notifications & Unified Form Controls
**Inspected files:**
- `src/admin/views/OverviewView.tsx` (lines 41–89)
- `src/admin/views/ActivityView.tsx` (lines 108, 147)
- `src/admin/views/MediaView.tsx` (lines 152, 201, 212, 411, 432, 481)
- `src/admin/ProjectForm.tsx` (multiple native inputs)

**Findings:**
- The "Attention" section in `OverviewView.tsx` is completely ephemeral and derived on the fly without persistence. There is no way to acknowledge or resolve alerts.
- Native HTML `<select>` elements look inconsistent with the dark cyber design system and lack accessible keyboard focus states.
- Hand-rolled SVG micro charts exist (`MiniBars.tsx`), but Activity and Overview lack rich event distribution charts (donut/pie) and trend areas (EvilCharts style).

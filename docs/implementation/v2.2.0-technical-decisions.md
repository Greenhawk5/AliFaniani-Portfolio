# v2.2.0 Architectural & Technical Decisions Log
**Ali Faniani Portfolio — v2.2.0**

This document records the rationale, alternatives considered, security implications, and operational impact of significant architectural decisions made during the v2.2.0 implementation.

---

## Decision 1: Sequential Migration Numbering
* **Context:** The Phase 0 audit noted conflicting suggestions in different sections (`0004_auth_log_indexing.sql` vs `0004_media_assets.sql` vs `0005_media_assets.sql`).
* **Decision:**
  - `migrations/0003_auth_log_country.sql` is preserved as-is.
  - `migrations/0004_auth_log_indexing.sql` will add indexing to `auth_log(ts DESC)`.
  - `migrations/0005_media_assets.sql` will create the `media_assets` table for R2 asset metadata.
* **Rationale:** Cloudflare D1 applies migrations strictly in alphabetical/lexicographical order. Sequential numbering ensures deterministic replay in local, preview, and production environments.

---

## Decision 2: Self-Healing Fallback in `logAuthEvent`
* **Context:** Remote inspection of production D1 revealed that `0003_auth_log_country.sql` was never applied in production, causing all `INSERT INTO auth_log (ts, ip, country, ok, note)` calls to fail silently.
* **Decision:**
  - Update `functions/lib/auth-log.ts` to attempt the 5-column INSERT (`ts, ip, country, ok, note`), and upon error, fall back to the 4-column legacy INSERT (`ts, ip, ok, note`).
  - Add explicit server-side error logging (`console.error`) rather than an empty catch block so unhandled database anomalies are visible in Workers/Pages real-time logs.
* **Rationale:** Defense-in-depth: the code must function correctly whether or not migration 0003 has finished running, preventing any loss of audit events during deployment windows.

---

## Decision 3: Server-Authoritative Throttled Session Expiration
* **Context:** Objective D requires a 15-minute idle timeout and 12-hour absolute timeout. Writing to D1 on every single API request to update `last_used_at` would burn D1 write limits (100k writes/month free tier).
* **Decision:**
  - Enforce both idle (15 min) and absolute (12 hr) timeouts on every authenticated request server-side in `functions/lib/session-auth.ts`.
  - Throttle updating `last_used_at` in D1 to once every 2 minutes.
  - Idle expiration formula: `now - last_used_at > 15 minutes`. With 2-minute write throttling, the effective idle window is strictly bounded between 13 and 15 minutes, while slashing D1 write volume by >85%.
  - `GET /api/admin/session` (read-only auth probes) will check validity but will NOT touch `last_used_at` or extend the session, ensuring passive browser polling cannot keep an inactive user logged in.
